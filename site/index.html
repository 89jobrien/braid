Runtime thread

One loop. Explicit boundaries.

The engine does not own providers, tools, storage, redaction, or context. It receives each capability through a port and coordinates them through a planner.

Assemble

Build a bounded snapshot and inject it as leading system context.

Plan

Choose a provider call, tool execution, or finish action.

Redact

Scrub outbound messages before the provider boundary.

Gate

Run policy hooks around each requested tool action.

Finish

Record completion and flush the session for inspection.

Observation is cross-cutting: the event sink records session start, provider response, tool call, tool completion, and session completion around the loop.

Sources: crates/braid-engine/src/engine.rs, crates/braid-hooks/src/executor.rs, and crates/braid-cli/src/main.rs.

The current weave

A small core with deliberate outer layers.

Orchestration

The engine coordinates; ports define the seams.

Engine<P, T, S, R, C> keeps provider, tool, event, redaction, and context dependencies visible in its type.

The planner owns control flow. Frontends stay thin. Infrastructure remains replaceable.

Safety

Policy wraps execution.

Ordered hooks can deny destructive commands before a tool runs.

Privacy

Redaction is a first-class port.

Messages cross provider and tool-result boundaries through explicit scrubbers.

Context

A map, not a manual.

Repository and task sources feed freshness-aware, budgeted snapshots.

Evidence

Sessions remain inspectable.

Lifecycle events can be persisted, replayed, rendered, and browsed in the TUI.
