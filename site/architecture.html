System map

Architecture that keeps its seams visible.

Domain values point inward. Infrastructure implements ports outside the core. CLI and TUI binaries compose the graph without becoming part of the engine.

Dependency rings

braid-model is the leaf. braid-ports defines the contracts. braid-engine coordinates a session. Outer crates implement providers, policy, persistence, context, components, protocol exposure, and operator setup.

The engine boundary

Inputs

A session and a planner

RunInput carries a session ID, messages, and an optional turn limit. A planner receives session state and selects the next action.

Injected dependencies

Five explicit seams

Provider, tool executor, event sink, redactor, and optional context provider are supplied to the generic engine rather than constructed inside it.

Composition roots

The CLI and TUI choose concrete providers, context sources, redaction rules, hooks, tools, and storage. That duplication is visible and currently tracked as an architectural pressure rather than hidden inside the engine.

Boundary rule: MCP owns protocol and tool exposure, hooks own external policy, redaction owns scrubbing, and observation owns session evidence. None of those concerns belongs in planner business logic.

Stable contracts

Canonical messages, content parts, tool calls, provider requests, events, transcripts, and context snapshots live in braid-model. The port crate then defines the behavior expected from each replaceable adapter.
